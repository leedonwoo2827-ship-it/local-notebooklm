# 고난도 퀴즈 프롬프트

자료 핵심에서 4지선다 객관식 문항 {{N}}개를 출제하라.

## 출제 규칙

- 한국어.
- **최고난도**: 응용·추론·비교·인과관계가 필요한 문항. 단순 정의·암기·연도/숫자
  단답형 문항은 제외.
- 정답이 자료에 근거해 명확한 사실 기반 문항만.
- `answer` 는 1~4 정수.
- 같은 개념의 중복 출제 금지.
- 출력은 JSON 만. 펜스·설명·머리말 없이 JSON 객체로 바로 시작.

## 매력적 오답 만드는 5가지 함정 패턴

보기 4개를 만들 때 정답 1개 외의 **매력적 오답 3개** 는 다음 5가지 중 골라 적용하라.
"전혀 관련 없음" 수준의 동떨어진 보기는 금지 — 모든 오답은 자료 어딘가에서
실제로 등장하는 정확한 사실을 비틀어서 만든다.

1. **순위 바꾸기** — 자료에 "A 가 가장 영향, B 가 두 번째" 라면, 오답은 "B 가 가장
   영향" 으로. 자료의 실제 순위를 인접한 다른 항목 순위와 교환.
2. **용어 바꿔치기** — 두 관련 개념의 정의를 서로 교환. 예: 광포화점의 정의를
   광보상점 정의로 적기. 두 개념 모두 자료에 등장하기 때문에 보기가 그럴듯해 보임.
3. **주객전도** — "A 가 B 한다" 를 "B 가 A 한다" 로 뒤집기. 예: 진과(자방벽 비대)와
   위과(꽃받침 발달)의 설명을 교환.
4. **마지막 절만 거짓** — 3~4문장으로 된 보기 중 앞부분 2~3문장은 모두 자료와 정확히
   일치, 마지막 한 문장만 잘못. 전체적으로 옳아 보여 찾기 매우 어려움. (가장 정교한
   함정 — 한 문항에 최소 하나 포함 권장)
5. **수치/범위 바꾸기** — 자료의 다른 항목 수치를 가져다 적용. 예: "수박은 5~7년
   휴작" 원문에 대해 오답은 "수박은 2~3년 휴작" (2~3년은 자료 안의 다른 작물 수치).

각 문항마다 적용한 함정 패턴 1~2개를 자연스럽게 녹여라. 한 회차(N문항) 안에서
함정 패턴이 한 쪽으로 쏠리지 않게 5가지를 골고루 사용.

## 해설(`rationale`) 작성 규칙

단순히 "정답은 X 이유" 한 줄이 아니라 다음 구조로 2~5문장으로 작성한다:

1. **정답이 옳은 근거** — 자료의 원문에 근접한 한 줄. 가능하면 페이지 인용.
2. **오답 3개 각각이 왜 틀렸는지 정확히 지목** — "이건 그냥 틀림" 이 아니라
   거짓 부분의 정확한 단어/구문을 짚어라.
   - 좋은 예: `보기 ②는 "종자번식에 비해 증식률이 높다"가 거짓. 자료(p.16)에 따르면
     영양번식의 단점이 "증식률이 낮음" 임.`
   - 좋은 예: `보기 ③의 "광합성 CO₂ 흡수=방출 광도"는 광포화점이 아니라 광보상점의
     정의임.`
   - 나쁜 예: `보기 ②는 사실과 다르다.` (어디가 어떻게 다른지 안 적음 — 금지)
3. **적용한 함정 패턴 명시** — `함정: 순위 바꾸기`, `함정: 마지막 절만 거짓` 식으로
   마지막에 한 줄 추가.

비전공자 검수자가 해설만 읽고도 "이 문항은 자료의 어느 부분이 어떻게 비틀어져
오답이 되었는지" 알 수 있어야 한다.

## 출처 작성 규칙 — **선지별 출처** 가 핵심

문항 단위 종합 출처(`source`) 외에, **각 보기(①②③④) 가 자료의 어디에서 왔는지**
를 `choice_sources` 배열에 따로 적어라. 검수자가 보기마다 원문 대조를 빠르게
할 수 있어야 한다.

- `source` (종합): 단원명 + 페이지 범위 — 예: `Ⅰ. 채소 / 78-80쪽`
- `choice_sources` (보기별): 4개 문자열 배열 — 가능한 한 좁은 페이지 단위
  - 좋은 예: `["p.78", "p.79", "p.80", "p.78 (함정: 다른 작물 수치)"]`
  - 허용: `["p.78-80", "p.78-80", "p.78-80", "p.78-80"]` (정확한 페이지 모르면 범위)
  - 금지: 빈 배열 또는 4개 미만

오답 보기의 경우, 그 보기가 **자료의 어느 부분을 비틀어서 만든 것인지** 출처에
짚어주면 더 좋다 (예: `p.16 (영양번식 단점을 장점으로 뒤바꿈)`).

### 페이지 번호는 책 인쇄 페이지 (필수)

- **반드시 책 하단에 인쇄된 페이지 번호** 를 사용한다. PDF 파일 내부의 페이지
  인덱스(1부터 시작) 가 아니다.
- 책 본문은 **12쪽부터** 시작한다. `p.1` ~ `p.11` 같이 비정상적으로 작은 숫자는
  **금지** (목차·서문 영역으로 단원과 무관).
- RAG context 의 `file_path` 메타데이터를 확인하라. 파일명이
  `01_채소_12-134.pdf` 라면 그 PDF 안의 모든 chunk 는 **책 12~134쪽 사이** 다.
  - 예: 파일 안 첫 chunk = 책 12쪽 부근, 마지막 chunk = 책 134쪽 부근.
  - 절대로 파일명 범위 밖의 페이지(예: `p.5`, `p.200`) 를 적지 마라.
- 정확한 페이지를 못 짚으면 파일명 범위 전체로 폴백 (예: `p.12-134`).

| PDF 파일명 | 책 페이지 범위 |
|---|---|
| `01_채소_12-134.pdf` | 12~134쪽 |
| `02_과수_135-262.pdf` | 135~262쪽 |
| `03_화훼_263-352.pdf` | 263~352쪽 |
| `04_시설원예_353-442.pdf` | 353~442쪽 |
| `05_생리장해_443-541.pdf` | 443~541쪽 |

이 범위를 벗어나는 페이지 번호는 환각이니 출력 금지.

## 출력 스키마

```
{
  "questions": [
    {
      "question": "문항 텍스트 (응용·추론 위주, 단순 암기 금지)",
      "choices": ["보기1", "보기2", "보기3", "보기4"],
      "choice_sources": ["p.78", "p.79", "p.80", "p.78 (함정 원본)"],
      "answer": 2,
      "rationale": "정답 근거 1줄 + 오답 ①③④ 각각의 거짓 부분 정확 지목 + 함정 패턴 명시",
      "source": "Ⅰ. 채소 / 78-80쪽"
    }
  ]
}
```
