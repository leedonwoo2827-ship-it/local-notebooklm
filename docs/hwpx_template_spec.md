# 📐 회사 HWPX 보고서 양식 작성 가이드

본 문서는 **회사 디자인팀(사업자측)** 이 Local NotebookLM 의 보고서 산출물에 적용할
HWPX 양식을 만들 때 따라야 하는 사양을 정의한다.

> 양식이 완성되면 **`assets/hwpx_template.hwpx`** 경로에 그대로 두면 자동 적용된다.
> (또는 `.env` 의 `HWPX_TEMPLATE_PATH` 변수로 다른 경로 지정 가능 — 향후 코드 지원 예정)

> 🚧 **현재 상태**: 본 문서는 사업자측에 양식 제작을 미리 요청하기 위한 스펙입니다.
> 보고서 산출물의 HWPX 출력 코드는 RAG 인덱싱 안정화 이후 별도 패치로 추가됩니다.
> 양식이 먼저 준비되어 있으면 코드 구현 시 바로 연결됩니다.

## 2. 한글 "스타일" 정의 (필수)

회사 디자인 룰을 한글의 **스타일** 기능에 박아두면 우리 코드가 본문 마크다운을
변환할 때 다음 스타일 이름을 그대로 매핑한다. 스타일 이름은 **정확히 일치**해야 한다.

| 스타일 이름 | 용도 | 권장 서식 |
|---|---|---|
| `제목` | 보고서 표지 큰 제목 | 24~28pt · 굵게 · 회사 메인 컬러 |
| `제목 1` | 1단계 헤딩 (장) | 18pt · 굵게 · 회사 메인 컬러 · 위 공백 |
| `제목 2` | 2단계 헤딩 (절) | 14pt · 굵게 · 짙은 회색 |
| `제목 3` | 3단계 헤딩 (항) | 12pt · 굵게 · 검정 |
| `본문` | 일반 본문 단락 | 10~11pt · 줄간격 160% |
| `목록` | 불릿/번호 항목 | 10~11pt · 들여쓰기 |
| `강조` | 핵심 키워드 | 굵게 · 회사 포인트 컬러 |
| `인용` | 출처 인용 / 박스 | 9~10pt · 이탤릭 · 좌측 라인 강조 |
| `코드` | 인라인 코드/용어 | 한컴 고정폭 또는 D2Coding |

> Markdown 의 `# / ## / ###` → `제목 1 / 제목 2 / 제목 3` 로 매핑됩니다.
> 일반 단락은 `본문`, 불릿은 `목록`, 강조 `**bold**` 는 `강조` 로 자동 변환.

## 3. 표지 페이지 (선택)

양식 첫 페이지에 표지 레이아웃이 있으면 그대로 유지된다. 다음 위치에 **빈 자리**를
남겨두면 우리 코드가 자동으로 채운다:

| 자리 | 채워질 내용 |
|---|---|
| 표지 제목 영역 | 보고서 제목 (LLM 생성) |
| 표지 부제 영역 | 작성일 + 노트북 이름 |
| 표지 하단 | 회사명/로고 (양식에 박아두기 — 우리 코드는 건드리지 않음) |

빈 자리 인식 방식은 표지 페이지에서 **"_제목_입력_"** 또는 **"_부제_입력_"** 같은
플레이스홀더 텍스트를 사용. 단순한 방식이라 향후 더 정교한 매핑(필드 마크 등)으로
업그레이드 예정.

## 4. 머리말 / 꼬리말

| 위치 | 권장 내용 |
|---|---|
| 머리말(홀수) | 보고서 제목 |
| 머리말(짝수) | 회사명 또는 로고 |
| 꼬리말 | 페이지 번호 (`- 1 -` 또는 `1 / N`) |

머리말·꼬리말은 양식에 박아두면 우리가 건드리지 않습니다.

## 5. 색상 권장

회사 BI 컬러를 자유롭게 사용해주세요. 우리 코드는 양식의 스타일 색을 덮어쓰지
않습니다. 일관성을 위해 다음 2~3색만 정의하면 충분:

- **메인 컬러** — 제목/헤딩에 사용
- **포인트 컬러** — 강조 텍스트·박스 테두리에 사용
- **보조 컬러** — 인용/캡션 등 보조 텍스트

양식 파일을 받으면:

이 사용됩니다.

## 10. 변환 파이프라인 (참고 — 개발자 측)

코드 구현 시 다음 두 가지 경로 중 선택 검토:

**A. LibreOffice CLI 변환** (현재 HWPX → PDF 입력 처리와 같은 방식)
- Markdown → ODT(LibreOffice) → HWPX 양식에 콘텐츠 주입 → 저장
- 장점: 의존성 적음, 이미 설치 권장 안내가 README 에 있음
- 단점: HWPX 스타일 매핑 정확도 검증 필요

**B. 한글 자동화 (HwpAutomation / 한컴 OLE)**
- 한컴 한글 설치된 환경 필수 (Windows 한정)
- 장점: 양식 100% 정확 재현
- 단점: 사용자 PC에 한글 설치 필수, 매크로 보안 문제 가능

→ 초기 PoC 는 A 로 진행, 회사 환경에 한글이 표준 설치되어 있으면 B 추가 검토.
